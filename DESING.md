# CEDHU Web Design Direction

## 1. Design Goal

The CEDHU website must communicate:

**technological + academic + human + clean**

The website should feel contemporary and forward-looking without losing the warmth and credibility expected from an educational institution.

The result must not look like a traditional school website.

It should feel like a modern digital experience created by an institution that understands education, technology, creativity and human development.

---

# 2. Core Design Principles

## Technological

Technology should be communicated through:

* interaction
* motion
* precision
* responsive behavior
* digital systems
* intelligent navigation
* visual experimentation

Avoid communicating technology through clichés such as:

* circuit board backgrounds
* neon blue gradients
* random code graphics
* futuristic HUD interfaces
* excessive glowing elements

Technology should be experienced, not decorated.

---

## Academic

Academic credibility should come from:

* strong typography
* structured hierarchy
* clarity
* editorial composition
* information architecture
* intentional use of space

The interface must feel serious without becoming rigid.

---

## Human

Humanity should be visible through:

* warm language
* approachable compositions
* subtle organic forms
* authentic photography when appropriate
* visual rhythm
* breathing space
* motion with personality

Avoid making the site feel cold or purely technological.

---

## Clean

Clean does not mean empty.

Clean means:

* every element has a reason
* spacing creates hierarchy
* decoration is controlled
* visual noise is avoided
* information is easy to understand
* motion supports navigation

---

# 3. Creative Direction

The website should combine:

```text
editorial design
+
digital interaction
+
institutional identity
+
experimental motion
```

The result should feel closer to a modern creative studio, cultural institution or technology-driven educational organization than to a conventional school website.

---

# 4. What We Are NOT Designing

Avoid visual patterns typical of generic institutional websites.

Do not default to:

* large photographic banner with text overlay
* carousel hero
* three-card feature row
* Bootstrap-style navbar
* floating WhatsApp-style UI as primary navigation
* generic SaaS cards
* endless rounded containers
* excessive shadows
* decorative gradients everywhere
* stock educational illustrations
* corporate icon grids
* symmetrical section after symmetrical section

Do not build an interface that looks like a template.

---

# 5. Composition

Prefer asymmetrical composition.

The layout should create tension between:

* typography
* empty space
* interactive elements
* imagery
* navigation

Avoid centering everything.

Use grids as invisible structure, not as visible boxes.

Large areas of negative space are encouraged only when they create composition and rhythm.

Empty space must feel intentional.

---

# 6. Hero Philosophy

The Hero is the first demonstration of the new CEDHU digital identity.

It must communicate the website concept immediately.

The entire desktop Hero should ideally be understandable within approximately one viewport.

Target:

```text
100svh
```

Do not require significant scrolling just to understand the main Hero composition.

---

# 7. Hero Content Hierarchy

The Hero should contain four conceptual layers:

```text
1. institutional identity
2. primary statement
3. interactive identity element
4. navigation
```

These layers should feel connected rather than independent.

---

# 8. Institutional Identity

CEDHU should be visible but not presented as a conventional large corporate logo header.

Institutional identification may include:

* CEDHU
* Centro de Desarrollo Humano
* location
* small institutional metadata

This information should sit quietly within the composition.

---

# 9. Headline

The headline must be bold enough to define the composition but must not consume the entire screen.

Current conceptual headline:

```text
Aprender para
transformar.
```

Preferred behavior:

* two deliberate lines on desktop when space allows
* large editorial typography
* strong contrast
* controlled line-height
* controlled maximum width

Avoid typography so large that the interface disappears behind it.

The headline should be dominant, not overwhelming.

---

# 10. Typography

Typography is a core visual element.

Use scale, spacing and contrast before using decorative graphics.

Prefer:

* large display typography
* compact line-height
* intentional tracking
* clear hierarchy
* readable body text

Avoid excessive font families.

Ideal direction:

```text
1 display family
+
1 body family
```

or one variable family capable of both roles.

Do not load a new font without design approval.

---

# 11. Color System

CEDHU institutional identity should remain recognizable.

Primary direction:

* institutional green
* institutional yellow
* warm off-white / bone
* near-black
* restrained neutral palette

Green should feel foundational.

Yellow should work primarily as an accent.

Avoid turning every section green and yellow.

Color should create hierarchy, not saturation.

---

# 12. Background

Prefer warm light backgrounds over pure white when appropriate.

Examples:

* bone
* warm ivory
* subtle neutral beige
* light gray-green

Avoid large decorative gradients unless motion or content gives them purpose.

---

# 13. Graphic Language

One recurring graphic system should help unify the website.

The preferred concept is the **CEDHU point / nucleus**.

Conceptually:

```text
CED · HU
     ●
```

The point can represent:

* connection
* origin
* human center
* knowledge
* interaction
* movement
* transformation

This point should progressively become part of:

* navigation
* Hero interaction
* transitions
* section indicators
* motion language

It must not become a decorative dot repeated everywhere without purpose.

---

# 14. Interactive Nucleus

The Hero should reserve an area for a future Rive-based interactive element.

That element should eventually feel like the living center of the interface.

Possible behaviors:

```text
idle
↓
cursor proximity
↓
reaction
↓
hover
↓
transformation
↓
click
↓
navigation response
```

The interactive element should visually connect to the navigation system.

It should not feel like a separate decorative illustration.

---

# 15. Bottom Navigation

The navigation is one of the defining elements of the website.

It must live near the bottom of the viewport.

Avoid reproducing a conventional top navbar.

The navigation should eventually feel like an interface object rather than a generic pill containing links.

---

# 16. Navigation Concept

Initial sections:

* Nosotros
* Académico
* Vida CEDHU
* Admisiones
* Noticias
* Contacto

The future experience may connect these options to the CEDHU nucleus.

Conceptually:

```text
                 ●
                 │
     Nosotros — CEDHU — Académico
                 │
          Vida / Noticias
```

This does not prescribe a literal radial menu.

It defines the conceptual relationship between the center and navigation.

---

# 17. Navigation Visual Rules

Navigation should be:

* compact
* sophisticated
* accessible
* readable
* responsive
* distinctive

Avoid:

* Bootstrap navbar appearance
* giant pill container with six uniform text links
* oversized shadows
* heavy glassmorphism
* hamburger navigation on desktop
* excessive borders

Rounded shapes are allowed but should not automatically become the main visual idea.

---

# 18. Mobile Navigation

Mobile behavior must be designed deliberately.

Do not simply shrink desktop navigation.

Options may include:

* horizontal touch navigation
* compact nucleus-driven menu
* expanded interactive navigation
* dedicated mobile interaction

A hamburger menu may be introduced only if it is the best usability solution.

Do not use it by default.

---

# 19. Interaction Philosophy

Motion must communicate something.

Use motion to:

* establish hierarchy
* reveal relationships
* guide attention
* reinforce navigation
* create personality
* explain state changes

Do not animate elements simply because animation is available.

---

# 20. Motion Style

Motion should feel:

* smooth
* controlled
* slightly playful
* responsive
* intentional

Avoid:

* constant bouncing
* excessive parallax
* random rotations
* long loading sequences
* dramatic scroll hijacking
* movement that delays access to information

---

# 21. GSAP Direction

Future GSAP usage should primarily support:

* text entrances
* section transitions
* scroll storytelling
* navigation state
* magnetic interactions
* subtle cursor behaviors
* relationship between page sections

Movement should feel coordinated across the interface.

---

# 22. Rive Direction

Rive should provide personality where vector state-based animation offers a real benefit.

Preferred uses:

* CEDHU nucleus
* navigation state
* meaningful interactive symbols
* microinteractions
* visual feedback

Avoid using Rive merely as animated decoration.

---

# 23. Spline Direction

3D is optional.

Use Spline only where three-dimensional interaction adds meaningful visual value.

Good potential location:

* Hero

Avoid spreading 3D elements throughout the entire website.

The overall visual identity should still work without 3D.

---

# 24. Imagery

Photography should feel authentic.

Prefer:

* real CEDHU spaces
* educators
* educandos
* laboratories
* academic activity
* technology
* human interactions

Avoid generic stock photography.

Photography should be treated editorially rather than placed inside generic cards.

Possible treatments:

* large crops
* unexpected framing
* masked transitions
* full-bleed sections
* scroll reveals

---

# 25. Cards

Cards are not prohibited.

Generic cards are prohibited.

Use a card only when content genuinely behaves as a self-contained object.

Avoid building the entire website as:

```text
card
card
card
card
card
```

Prefer layouts where content participates in the composition.

---

# 26. Borders and Shadows

Use sparingly.

Borders:

* subtle
* functional
* structural

Shadows:

* minimal
* soft
* reserved for hierarchy when necessary

Do not use shadows as the default way of separating every element.

---

# 27. Rounded Corners

Rounded corners should not define the entire site.

Avoid making every:

* image
* card
* button
* navigation
* section
* container

a rounded rectangle.

Mix hard and soft geometry intentionally.

---

# 28. Visual Rhythm

Sections should not all share the exact same layout.

The website should alternate between:

* dense and open
* typographic and photographic
* static and interactive
* horizontal and vertical rhythm

Variation must still feel like one system.

---

# 29. Section Transitions

Future transitions may use:

* scale
* mask reveal
* typography movement
* image cropping
* controlled background change
* nucleus movement

Avoid arbitrary decorative transitions.

---

# 30. Microinteractions

Microinteractions should provide feedback.

Examples:

* navigation hover
* CTA response
* link underline behavior
* cursor proximity
* nucleus response
* section state indicator

Every interaction should remain understandable without motion.

---

# 31. Cursor

A custom cursor may be explored later.

If implemented, it must enhance interaction.

Possible context states:

```text
default
view
open
drag
next
```

Do not replace the native cursor unless the new behavior improves usability.

---

# 32. Accessibility and Design

Visual experimentation must never reduce usability.

Always preserve:

* readable typography
* visible focus states
* sufficient contrast
* keyboard interaction
* reduced motion
* semantic navigation
* understandable content order

Accessibility is part of the design system.

---

# 33. Performance and Visual Design

A visually impressive interface that performs poorly is considered a failed design.

Avoid:

* unnecessary autoplay video
* oversized images
* excessive animation runtimes
* multiple heavy 3D scenes
* large JavaScript bundles

Motion should be selectively applied.

---

# 34. Desktop Hero Target

A desirable conceptual balance:

```text
┌───────────────────────────────────────────────┐
│ CEDHU                         institutional   │
│                                               │
│                                               │
│  Aprender para              interactive       │
│  transformar.                 nucleus         │
│                                               │
│  supporting message                           │
│                                               │
│  Explore ↓                                    │
│                                               │
│                  navigation                   │
└───────────────────────────────────────────────┘
```

This is a conceptual hierarchy, not a rigid wireframe.

---

# 35. Avoid Template Thinking

Before introducing a pattern, ask:

> Does this feel specific to CEDHU?

If the same interface could belong unchanged to:

* a fintech
* a SaaS product
* a consulting firm
* any other school

then the visual decision is probably too generic.

---

# 36. Reference Philosophy

We may study experimental websites such as Tonemaki for:

* interaction principles
* motion
* composition
* navigation ideas
* digital personality

Do not copy:

* layouts
* typography
* graphic assets
* exact animations
* brand language

The goal is to translate principles into a distinct CEDHU identity.

---

# 37. Primary Design Rule

The interface itself should communicate innovation.

Do not decorate a conventional website and call it technological.

The structure, interaction, typography and navigation must collectively express:

**technology + academia + humanity.**

---

# 38. Final Decision Test

Every major visual decision should satisfy at least one of these goals:

* improves hierarchy
* improves usability
* reinforces CEDHU identity
* communicates innovation
* adds human warmth
* creates meaningful interaction

If it satisfies none of them, remove it.
